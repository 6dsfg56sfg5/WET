# 🏢 Сдача-приёмка квартир (клиент-серверное веб-приложение)

Веб-система для приёмки квартир от застройщика: объекты → корпуса → помещения,
история осмотров с фотографиями нарушений и исправлений, уровни доступа сотрудников,
бекап/восстановление всех данных.

## Запуск

```bash
cd acceptance_app
pip install -r requirements.txt   # fastapi, uvicorn, sqlalchemy, python-multipart, pydantic
python run.py                     # сервер на http://0.0.0.0:8000
```

Откройте в браузере **http://localhost:8000** — сначала экран авторизации.

Демо-учётные записи (создаются автоматически при первом запуске):

| Логин     | Пароль        | Уровень | Права                                  |
|-----------|---------------|---------|----------------------------------------|
| admin     | admin123      | 3       | объекты, корпуса, сотрудники, бекап    |
| inspector | inspector123  | 2       | помещения, нарушения, история, акты    |
| viewer    | viewer123     | 1       | только просмотр                        |

Переменные окружения: `ACCEPTANCE_DB_URL` (по умолчанию SQLite в `data/acceptance.sqlite3`,
можно указать PostgreSQL), `ACCEPTANCE_SECRET` (секрет подписи токенов — смените в проде).

## Функциональность

- **Авторизация** сотрудников, 3 уровня доступа; роли проверяются и на API (403), и в UI.
- **Уровень 3**: создание/редактирование/удаление объектов и корпусов (название объекта; адрес,
  этажи, квартиры на этаж у корпуса; автогенерация квартир), прикрепление сотрудников к объектам,
  управление сотрудниками, бекап/восстановление.
- **Уровень 2**: просмотр и редактирование помещений (номер, этаж, тип жилого/нежилого, отделка,
  статус, площадь, покупатель), создание нарушений, добавление записей в историю осмотра
  (фото нарушения / фото исправления + текст), смена статуса нарушения, прикрепление акта.
  Удалять записи истории нельзя — API удаления не существует.
- **Уровень 1**: только просмотр.
- **Экраны**: список объектов со статистикой помещений по статусам → раскрытие корпуса
  (аккордеон с краткой статистикой) → «шахматка» по этажам с цветными шариками номеров квартир
  (цвет = статус помещения, пунктирная рамка = нежилое) → карточка помещения с историей нарушений,
  полем покупателя и файлом акта приёма-передачи.
- **Статусы нарушений** с цветовыми маркерами: к устранению 🔴, в работе 🟠, на проверке 🔵,
  устранено 🟢, закрыто ⚪. **Статусы помещений**: не осмотрено, готово к передаче, гарантия,
  выявлены нарушения, переданы с замечанием, приняты отделочные работы, отказано.
  **Отделка**: черновая, white box, чистовая, гибридный white box.
- **Бекап**: `GET /api/backup` отдаёт zip (data.json + все загруженные файлы),
  `POST /api/restore` замещает данные целиком — «защита от дурака».

## Проверка API

```bash
python run.py &            # или отдельным терминалом
python test_api.py         # ~40 проверок: роли, нарушения, фото, акты, бекап/restore
```

- **Подъезды**: у корпуса задаётся количество подъездов (1–50); при автогенерации квартиры распределяются по подъездам поровну на каждом этаже; шахматка группирует помещения «Этаж → Подъезд»; подъезд можно изменить в редакторе помещения.
